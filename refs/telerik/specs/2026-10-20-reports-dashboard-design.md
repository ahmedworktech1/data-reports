# تصميم: لوحة تحكم تقارير مستقلة (Reports Dashboard)

**التاريخ:** 2026-10-20
**الحالة:** مسودة — بانتظار مراجعة المستخدم
**المنهج المعتمد:** تطبيق ويب ASP.NET Core مستقل على نفس الـ IIS، ينادي خدمة التقارير الحالية
(توصية نموذج Jev — ثقة 0.82). المرجع: `refs/telerik/index.md`.

---

## 1. الهدف
تطبيق ويب **مستقل** (لوحة تحكم) يعرض تقارير الـ ERP الحالية بشكل أسرع وأوضح، بدون لمس
مكتبات Telerik أو تعديل الـ ERP.

## 2. الأهداف (MVP)
1. قائمة تقارير واضحة + بحث سريع + تصنيفات/مجلدات.
2. **فتح التقرير بضغطة واحدة** (الأولوية الأولى حسب Jev).
3. تقارير **مفضلة** و**أخيرة**.
4. شكل أبسط وأوضح من الشاشة الحالية.
5. طبقة مستقلة قابلة لإضافة أي ميزة جديدة مستقبلاً.

## 3. خارج النطاق
- نسخ/تعديل/إعادة توزيع مكتبات Telerik (Progress) — مرخّصة تجارياً.
- تعديل كود الـ ERP الحالي.
- بناء مصمم تقارير جديد.
- تغيير صيغ التقارير أو مصادر بياناتها.

## 4. الوضع الحالي (السياق)
- الـ ERP: **ASP.NET Core 8 + IIS (InProcess) + SQL Server**.
- **Telerik Reporting 17.1.23.718** (7 مكتبات، موثّقة في `refs/telerik/index.md`).
- التقارير في مجلد `Reports/` (898 ملف).
- العارض الحالي: **Telerik HTML5 Report Viewer** → `serviceUrl=/api/reports/`.
- كتالوج التقارير والصلاحيات: جدول **`erpx_sandoaa_br.Brca.ReportRoles`** (718 صف، 28 عمود).
  أهم الأعمدة واستخدامها في اللوحة الجديدة:

  | العمود | الاستخدام |
  |--------|-----------|
  | `Id` | مفتاح التقرير (بيرتبط بالمفضلة/الأخيرة) |
  | `DescriptionArabic` / `DescriptionEnglish` | اسم التقرير المعروض |
  | `ReportNameArabic` | **اسم ملف التقرير الفعلي** (مثل `kashfHesabAshry1.trdx`) — ده اللي بيتمرر للمشغّل |
  | `Module` | تصنيف التقرير حسب الموديول |
  | `MvcItemId` | الشاشة الأصلية (مثل `gl\|ReportGlaccstatn\|Index`) |
  | `PermissionGroups` | صلاحية ظهور التقرير للمستخدم |
  | `DatabaseName` | قاعدة البيانات (فهرس) |

## 5. البنية العامة
```
[المتصفح]
   │
   ▼
[تطبيق لوحة التحكم الجديد]  ──ASP.NET Core 8 MVC──  (موقع IIS مستقل)
   │  - شبكة تقارير + بحث + تصنيفات
   │  - يضمّن Telerik HTML5 Report Viewer
   │  - يقرا BRC.ReportRoles (قراءة فقط)
   ▼
[قاعدة بيانات الـ ERP]
   │
   └──► [خدمة التقارير الحالية /api/reports/]  (جوه الـ ERP)
```

## 6. المكونات
### 6.1 الصفحات
- `/` لوحة التحكم: شبكة تقارير (بحث + فلترة + تصنيفات/مجلدات).
- `/Report/Open/{id}` فتح التقرير (مشغّل HTML5).
- `/Favorite/*` إضافة/إزالة مفضلة.
- `/Recent/*` (ضمن اللوحة).

### 6.2 الخدمات
- `IReportCatalogService`: قائمة التقارير من `Brca.ReportRoles` + فلترة بالصلاحيات.
- `IFavoritesService`: جدول `DashboardFavorites`.
- `IRecentService`: جدول `DashboardRecent`.
- `IReportViewerConfig`: تهيئة المشغّل (`serviceUrl`, report name, parameters).

## 7. نموذج البيانات
**جديد** (في قاعدة الـ ERP `erpx_sandoaa_br`):
- `DashboardFavorites (UserId, ReportRoleId, AddedAt)`
- `DashboardRecent (UserId, ReportRoleId, OpenedAt)`

**قراءة فقط:**
- `Brca.ReportRoles`

## 8. المصادقة والصلاحيات
- **توصية:** مشاركة تسجيل دخول الـ ERP (نفس ASP.NET Identity + نفس الكوكي) → المستخدم يفتح
  اللوحة بلا تسجيل دخول جديد.
- الصلاحيات: نفس منطق `PermissionGroups` في `Brca.ReportRoles`.
- بديل (لو التطبيق لجمهور خارجي): حسابات منفصلة.

## 9. التكامل مع خدمة التقارير الحالية
- مشغّل **Telerik HTML5 Report Viewer** جوه التطبيق الجديد.
- الإعداد: `serviceUrl = https://<erp-host>/api/reports/` + `report = ReportNameArabic` (اسم ملف
  التقرير الفعلي من `Brca.ReportRoles`).
- التطبيق الجديد **مش** بيشغّل محرك Telerik بنفسه، ولا بيلمس ملفات `.trdx`.
- باراميترات التقرير: قيم افتراضية، أو شاشة فلتر بسيطة بتمرر للمشغّل.

## 10. الاستضافة والنشر
- موقع IIS جديد + Application Pool خاص (نفس السيرفر).
- رابط جديد (مثلاً `https://reports.<domain>` أو `http://<server>:5010`).
- تطبيق .NET 8 مستقل (مجلد منفصل عن الـ ERP).

## 11. معالجة الأخطاء
- تقرير غير موجود → رسالة واضحة.
- صلاحية مرفوضة → إخفاء/منع.
- خدمة التقارير غير متاحة → رسالة + retry.
- مستخدم غير مسجّل → توجيه لتسجيل الدخول.

## 12. الاختبار
- Unit tests: `ReportCatalogService`, `FavoritesService`, `RecentService`.
- اختبار تكامل: التواصل مع `/api/reports/`.
- اختبار متصفح (Playwright): البحث، الفتح بضغطة، المفضلة.

## 13. التوسع المستقبلي (بدون مساس بالـ ERP)
- تصدير/مشاركة، إشعارات، جدولة، تقارير مخصصة، لوحات إدارة.

## 14. افتراضات وأسئلة مفتوحة
1. **المصادقة:** لم تُحدد — التوصية: مشاركة الهوية. (محتاج تأكيدك)
2. **الرابط/النطاق:** أين يُنشر التطبيق؟
3. **الفلتر:** هل كل تقرير محتاج شاشة فلتر، ولا القيم الافتراضية تكفي؟
4. **التصنيفات:** هل نستخدم `Module` ولا `ReportFolder` ولا `MvcItemId` كشجرة التصنيفات؟

## 15. قرارات مُتخذة
- **مصدر قائمة التقارير:** `Brca.ReportRoles` (الاسم المعروض من `DescriptionArabic`، وملف التقرير من
  `ReportNameArabic`، والصلاحية من `PermissionGroups`).
- **العرض:** مشغّل Telerik HTML5 جوه التطبيق الجديد (نفس المشغّل الحالي) — بدون محرك Telerik جديد.
- **النشر:** تطبيق .NET 8 مستقل على نفس الـ IIS.
